## 1. Правило «откат внутри силы» — главное

    rsi48 >= 56.3761  И  rsi6 <= 33.7947  ->  LONG
    тейк 1.0 ATR, стоп 3.0 ATR, удержание 48ч — как у банка
    РЕЖИМНЫЙ ГЕЙТ НЕ ПРИМЕНЯТЬ
    дневной фильтр BTC против SMA(50) оставить

### Что придётся тронуть

**а) Признаки.** `src/pullback_bank.py`, функция `features()` считает `atr, rsi2, rsi14, slope,
ret24, rng, volreg, btc24, body, hour`. Ни `rsi6`, ни `rsi48` в ней нет. Добавить две строки:

```python
        rsi6=_rsi(c, 6),
        rsi48=_rsi(c, 48),
```

Проверено: исследовательская функция, на которой правило найдено, — это буквально `PB._rsi`
(`feat2._rsi` возвращает `PB._rsi(c, n)`). Сглаживание одно и то же, пороги переносятся без
искажения.

**б) Обход режимного гейта.** `hourly_signals()` сейчас отбрасывает час, если он не попал в режимный
интервал, и только потом смотрит правила:

```python
        j = bisect.bisect_right(starts, close) - 1
        if j < 0 or not (iv[j][0] <= close < iv[j][1]) or np.isnan(F["atr"][i]):
            continue
        side = iv[j][2]
        if side == "LONG" and btc_down(close):
            continue
        for k, r in enumerate(rules):
```

Нужен флаг у правила. Форма правки:

```python
        if np.isnan(F["atr"][i]):
            continue
        j = bisect.bisect_right(starts, close) - 1
        inside = j >= 0 and iv[j][0] <= close < iv[j][1]
        side = iv[j][2] if inside else None
        down = btc_down(close)
        for k, r in enumerate(rules):
            want = r.get("side", "LONG")
            if not r.get("gateless") and (not inside or side != want):
                continue
            if want == "LONG" and down:
                continue
```

**в) Само правило** в набор:

```python
{"name": "pullback_in_strength", "tp": 1.0, "sl": 3.0, "gateless": True,
 "conds": [("rsi48", ">=", 56.3761), ("rsi6", "<=", 33.7947)]}
```

### Чего правка НЕ касается

Ни одно существующее правило банка не меняется. Гейт для них остаётся как был — новый флаг
`gateless` действует только на новое правило. Геометрия, удержание, размер позиции, все живые
сторожа — без изменений.

## 4. Отсечка стопа на 0.10 — безопасность

При плече 10 и изолированной марже ход в 10% съедает маржу. У **97 сделок из 2476 (3.9%)** стоп
шире этого — до 66% цены. На них биржа закроет позицию раньше бота, со штрафом за ликвидацию,
которого в модели нет.

`src/pullback_live.py:253` считает `sl_frac0` и применяет его только к урезанию маржи. Проверки,
что стоп вообще достижим, нет. Урезание по `stop_ref` тут не спасает и не может: оно масштабирует
позицию, а расстояние до ликвидации задаётся ПЛЕЧОМ.

Правка — одно сравнение на входе:

```python
        sl_frac0 = r["sl"] * w["atr"] / w["level"]
        if sl_frac0 > 0.10:        # стоп дальше ликвидации при плече 10
            return
```

Стоит 4% денег. Я считаю это оправданной ценой.

## Чего эти числа не обещают

Модель, а не живой результат. За два дня я нашёл в собственном учёте пять ошибок, каждая двигала
итог на десятки процентов; найдётся ли шестая — не знаю.

Заливка на бирже 84-86% — примерно каждый седьмой сигнал не открывается. В модели вход рыночный,
промахнуться нельзя, так что это расхождение остаётся неучтённым.

Пять лет данных — это один рынок. Правило работало во всех пяти и не выдыхается (первая половина
истории +0.111R, вторая +0.185R), но гарантий на следующие четыре года нет ни у кого.

И у симулятора нет механизма разорения: при высоком риске он считает дальше там, где живой счёт
ликвидировали бы. Защёлка 15% — единственное, что удерживает его числа в реальности.

## 6. Правило short_pop_in_downtrend: стоп 2.0 ATR, тейк 1.5 ATR

Правило `rsi2 >= 71.02 И rsi14 <= 35.22 -> SHORT`. Остальные четыре правила банка не меняются — у
них своя геометрия слепую проверку не прошла (2–3 года из 5).

Правка — только значения в описании этого правила в `RULE_SETS` (`src/pullback_bank.py`): `sl=2.0`,
`tp=1.5`. Живой вход уже берёт стоп и тейк из самого правила (`src/pullback_live.py:253`, `:293-294`
читают `r["sl"]` и `r["tp"]`), удержание 48ч общее и не меняется.

Проверки: +66% и +53% денег при фиксированном риске 1.4% на двух наборах монет, просадка при этом
НИЖЕ на обоих; лучше в 5 годах из 5 на обоих; слепой выбор стопа по четырём годам лучше нынешнего в
5 из 5; ровная площадка стоп 1.75–2.5 × тейк 1.25–2.0. Опасные края: стоп 1.5 и удержание 72ч
загоняют счёт в защёлку 15%. Свой винрейт правила падает с 80% до 67%.

## 7. Второй источник отката: то же правило на 2-часовых свечах

Пороги те же (`rsi48 >= 56.3761 И rsi6 <= 33.7947`, LONG, без режимного гейта, с фильтром BTC),
только признаки и ATR считаются на 2ч свечах. Стоп 3 ATR и тейк 1 ATR — от 2ч ATR.

Что придётся тронуть:

**а) Генератор сигналов.** `hourly_signals()` жёстко завязан на час:

```python
    T1, B1 = build_bars(t15, a15, HOUR)
    ...
        close = int(T1[i]) + HOUR
```

Нужен параметр размера свечи `sec` (по умолчанию `HOUR`, чтобы банк не изменился) и его подстановка в
обе строки. `MIN_HOURS = 720` на 2ч свечах означает 60 дней разогрева — истории хватает.

**б) Живой цикл.** `src/pullback_live.py:134` будит проверку на часовой границе
(`close = now - now % PB.HOUR`). Источник на 2ч должен проверяться на 2-часовой границе и
отдельным вызовом генератора с `sec=7200` только для правила отката.

**в) Удержание.** 48 свечей по 2ч — это 96 часов, больше потолка в 72 часа. Для этого источника
удержание 72ч, для всех остальных остаются 48ч. Сейчас удержание общее (`HOLD_BARS`), значит нужно
удержание на уровне источника или правила.

**г) Приоритет.** Одна позиция на монету, как сейчас: при совпадении во времени банк первым, потом
откат на 1ч, потом на 2ч.

Проверки: +15% денег при 1.4% на обоих наборах монет, при равной просадке +14% и +6%, лучше в 4 годах
из 5 на обоих; при реальной заливке 85% +11% ($2202 -> $2440). Свечи 90м, 3ч и 4ч проверены и не взяты.
